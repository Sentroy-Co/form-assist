# ADR 001: portable contracts, explicit runtime entry points

Status: accepted for the first vertical release (2026-11-06).

Use a strict TypeScript npm workspace with one installable package and explicit subpath exports: core, server, server/node, providers, browser, native, react, react-hook-form and ui. This reduces publishing coordination while preserving dependency boundaries. Consumers of core never import browser, React, Node storage or provider credentials. Providers use fetch rather than vendor SDKs and accept an explicit model ID. The UI is registered explicitly as autonomous Shadow DOM custom elements, with no DOM access during module import.

JSON Schema 2020-12 describes forms. Runtime authorization, option resolution, credentials and setters stay outside serialized contracts. Server-registered schemas and authorized connection/model IDs are authoritative. Proposals are revision-bound, atomic, allowlisted replace/add/remove plans; user approval precedes state writes. Browser applies validation again and supports conflict-safe undo. UI renders all untrusted strings as text.

Node CLI and encrypted file storage have isolated entry points. The HTTP handler uses Web Request/Response APIs for Node and Workers. No public proxy, hosted account, telemetry, automatic submit, publishing or paid resource provisioning is included. Rust and C# call the same Node CLI protocol instead of duplicating the engine.

First vertical: core + guarded server + explicitly registered UI + native/React/RHF + CLI and fixture demo. Other framework integrations remain planned until independently exercised. Live provider tests require deliberately supplied test credentials; transport contract tests do not establish live model support. Package name is provisional; npm publishing requires separate explicit authorization. License remains proprietary/unlicensed pending owner choice.
