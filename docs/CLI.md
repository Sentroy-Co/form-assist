# CLI protocol

Requires Node.js 22 or newer. Build with `npm run build`; invoke `node packages/form-assist/dist/cli/index.js` or the installed `form-assist` executable. Rust and C# examples invoke this same process, not a separate engine. Run each from its example directory with `cargo run` or `dotnet run`; both compare the shared request and response fixtures. Both clients were verified against the shared fixtures with Rust 1.99.1 and .NET SDK 8.0.427. After building, run `scripts/integration-languages.sh` from the repository root to repeat both checks; it uses local toolchains in `.tools` when present, or tools on PATH.

`init` creates `form-assist.config.json` without overwriting an existing file; `--config FILE` selects another file. Register form snapshots under `forms`, keyed by form ID, and connections under `connections`, keyed by connection ID. A connection has `type`, `models` (an explicit allowlist), and `credentialEnv` (the name of a server environment variable). Supported types are `openai`, `anthropic`, `gemini`, `workers-ai`, `cloudflare-gateway`, `vercel-gateway`, and `openai-compatible`. Workers requires `accountId`; Cloudflare Gateway requires `accountId`, `gatewayId`, `upstream`, and optionally `upstreamCredentialEnv`; compatible endpoints require `endpoint` and `allowedHosts`. Never put credential values in arguments or configuration. Configure environment variables outside the CLI.

`validate-schema --stdin` accepts a complete form snapshot. `connections list --json`, `models list --connection ID --json`, and `doctor --json` return JSON. `propose --connection ID --model ID --stdin --json` accepts a version 1 `ProposeRequest` and emits a validated `ChangePlan`. The command connection and model must agree with any included in the request. Registered schemas and allowed models remain authoritative. `--fixture demo` explicitly enables the deterministic demo connection and form; it returns a validated empty plan and makes no provider call.

`--stream` emits newline-delimited JSON version 1 `start`, then `result` or `error` events. Each complete result contains the same plan as JSON mode; no partial proposal is applied. Standard output is reserved for JSON, and human notices go to standard error. Failure JSON has an `error` object with stable `code` and `message`; stream errors carry the request ID. Exit codes: 0 success, 2 usage/input, 3 configuration/resource, 4 authorization, 5 timeout, 6 rate limit, 7 invalid provider output, 130 cancellation, 1 other failure. Ctrl+C aborts the request; a closed output pipe stops the process. Server limits also apply. Provider transports may not offer incremental generation: streaming here reports lifecycle events, not tokens.
